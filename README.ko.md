# EG OS

**에이전트를 위한 meta-harness 예요.** 각 에이전트가 이미 쓰는 하네스와 **함께** 돌고, 그 하네스를 대신하지 않아요. [EstreGenesis](https://github.com/SoliEstre/EstreGenesis) 의 안정판이고, Observatory (`ov.estre.so`) 가 제공·권장하는 meta-harness 예요.

이 판이 정확히 무엇을 담았고 상류의 어느 커밋에서 조립됐는지는 [EDITION.md](EDITION.md) 에 있어요.

---

## 5분

플랫폼을 설치하는 게 아니에요. 에이전트에게 파일 하나를 주는 거예요.

1. **시드 하나를 프로젝트에 복사**하세요 — `AI_Native_프로젝트_시드_프롬프트_Compact.md` 로 시작하면 돼요.
2. **에이전트에게 그걸 가리키세요.** 읽고 나서 *당신 프로젝트의* `AGENTS.md` 를 써요 — 당신의 스택, 당신의 관례, 당신의 제약으로요.
3. **첫 걸음은 여기까지예요.** 이제 에이전트가 당신 코드베이스에 대해 알아낸 걸 **적어 둘 자리**가 생겨요. 세션마다 다시 알아내지 않아도 되고요.

여기까지 서버도, 플러그인도, 계정도 필요 없어요.

더 필요해지면 모듈을 하나씩 얹어요:

```
/plugin marketplace add SoliEstre/eg
/plugin install estregenesis@eg-os
```

모듈은 서로 독립이에요. 하나만 깔아도, 안 깔아도 돼요.

## 어디에 얹히나

| 층 | 무엇 |
|---|---|
| **펌웨어** | 모델과 벤더 자신의 하네스·클라우드 런타임 — Claude Code · Codex · Grok · Antigravity · 벤더가 호스팅하는 클라우드 에이전트. 에이전트 하나를 부팅하고 도구를 돌려요. |
| **버스** | 에이전트가 도구·서로와 말하는 열린 규약 — MCP · A2A. |
| **EG OS** | 그 위에서 여러 에이전트가 — 대개 여러 벤더의 에이전트가 — 한 일을 같이 하는 층. |
| **당신의 프로젝트** | 그 일이 향하는 곳. |

예전엔 이런 층이 필요했던 일을 벤더가 계속 흡수하고 있어요 — 한 계정 안의 에이전트끼리는 이미 메시지를 주고받고, 한 런타임 안의 위임은 기본이에요. 벤더가 주지 않는 건 EG OS 가 중심에 둔 부분이에요 — **에이전트끼리 하는 말을 읽을 수 있고**, 결정은 메시지에 실려 가는 대신 사람을 기다리고, 작업 상태는 어느 한 벤더보다 오래 남아요. 그래서 EG OS 는 하네스와 경쟁하지 않고 **함께** 가요 — 에이전트와 벤더가 늘수록 볼 게 많아지니까요.

**벤더 클라우드에 사는 에이전트**(상주 클라우드 컴퓨터·호스팅 에이전트 세션)는 워커가 아니라 사람을 대신해 움직이는 자율 피어로 붙어요. 그 경로는 규격에는 있지만 아직 열리지 않았어요 — 보드의 MCP 채널은 stdio 로만 돌고, 내 컴퓨터의 보드는 벤더 클라우드에서 닿지 않아요. 그게 닿도록 보드를 서빙하고, 여러 보드를 한곳에서 지켜보고 결정하게 하는 것이 Observatory (`ov.estre.so`) 가 만들어지는 이유예요. 개발 중이에요.

## 무엇을 관리하나

「OS」는 주장이니까 구체적으로 적을게요. 운영체제는 프로세스 사이에서 **희소 자원**을 조정하는 것이고, 코딩 에이전트에게 그 자원은 **문맥(context)** 이에요. 나머지는 거기서 따라와요.

| 운영체제가 관리하는 것 | EG OS 의 대응물 |
|---|---|
| CPU 시간 · 스케줄링 | **Superscalar** — 몇 갈래로 펼칠지, 각 갈래를 무엇으로 돌릴지 |
| 메모리 | **문맥** — 압축 생존 · 핸드오프 카드 · 브리핑 티어링 |
| 프로세스 간 통신 | **Constellation** — 에이전트끼리의 대화가 보이고·결정되고·기록되는 곳. 자체 채널이 운반해도 보드가 봐요 |
| 장치 드라이버 | **하네스 어댑터** — 좌석 계약(Pantty)과 하네스별 바인딩. 벤더마다 런타임이 달라도 같은 방식으로 꽂혀요 |
| 영속 저장 | **Compendium** 어휘고 · 보드 상태 · 남는 교훈 |
| 권한 · 보호 링 | 결정 게이트 · 에스컬레이션 기준 · **Ultrasafe** 점검 |
| 패키지 관리 | 이 마켓플레이스 · 플러그인 · 시드 티어 |

에이전트에게 문맥은 초기 운영체제에게 메모리 같은 거예요 — 제일 먼저 바닥나고, 나머지 설계가 전부 그걸 중심으로 짜이는 것.

## 이건 아니에요

**가볍지 않아요.** 모듈 스펙 일곱, 플러그인 여덟, 라이브 보드 서버, MCP 서버. 이걸 가볍다고 하면 첫 접촉에서 깨질 기대를 심는 거예요.

정직한 프레임은 **「큰 시스템, 작은 첫 걸음」** 이에요 — 어떤 OS 와도 맺는 것과 같은 관계고요. 다 배우고 명령 하나를 치지는 않잖아요.

**import 하는 프레임워크가 아니에요.** EG OS 의 대부분은 에이전트가 읽는 관례·규격·규율이에요. 런타임 부분은 선택이고 가산이에요.

## 판(edition)과 업그레이드

판 이름은 날짜이고 **주 단위**로 끊어요: `2026.08.1` 이 8월의 첫 판, `2026.08.2` 가 두 번째 판이에요. 한 판은 **함께 검증된 뒤 그대로 둔** 모듈 버전들의 조합이에요.

주 단위인 건 사람이 실제로 업무·유지보수·사이드 프로젝트를 오가는 주기에 맞춘 거예요 — 한 판이 대략 「이번 주에 집어 든 것」의 단위가 돼요.

판 사이에 다음은 이주 안내 없이 깨지지 않아요 — 시드 마커와 티어 이름, 플러그인 id 와 스킬 이름, 보드 프레임 계약(가산만). 스펙 안의 절 번호와 내부 런타임 구조는 그런 약속을 하지 않아요. 전문은 [COMPATIBILITY.md](COMPATIBILITY.md) 에 있어요.

검증된 조합 대신 최신 작업을 원하시면 상류 저장소를 직접 쓰세요 — 하루에 여러 번 움직이고, 그게 맞바꾸는 값이에요.
